# release2reel

**Turn your release notes into a product-update video — one command, ~$2, on the [Runway API](https://docs.dev.runwayml.com/).**

Every dev team ships releases; almost none turn them into media. Release notes are the most under-leveraged marketing asset in open source — written, accurate, already public, and read only by the people who read changelogs. `release2reel` makes "release → 20-second update video" a zero-effort default, the way CI made "commit → build" a default.

```
CHANGELOG.md / GitHub release body
        │
        ▼
[1] Parse & rank        top 2–4 highlights (conventional-commit aware, falls back to headings/bullets)
        ▼
[2] Shot list           each highlight → {image_prompt, motion_prompt, overlay_text}
        │                 LLM-written by default (Claude), or deterministic templates with --no-llm
        ▼
[3] Keyframes           gen4_image @ 720p — one consistent style descriptor across scenes
        ▼
[4] Motion              gen4.5 image_to_video, 5s per scene, SDK async task polling
        ▼
[5] Assemble            ffmpeg: title card + text overlays + concat (+ README-ready .gif)
        ▼
out/v2.1.0.mp4          → Action mode: attached to the GitHub release automatically
```

## Quickstart

```bash
pip install git+https://github.com/soos3d/release2reel.git
# needs ffmpeg on PATH: apt install ffmpeg / brew install ffmpeg

# 1. Zero keys, zero credits — see the shot list and cost before spending anything
release2reel examples/CHANGELOG.md --tag v2.1.0 --dry-run

# 2. Still zero keys — full pipeline with locally generated placeholder clips
release2reel examples/CHANGELOG.md --tag v2.1.0 --mock

# 3. The real thing
export RUNWAYML_API_SECRET=key_...   # https://dev.runwayml.com
release2reel CHANGELOG.md --tag v2.1.0
```

That's it: `out/v2.1.0.mp4` (≤30s, 720p) plus `out/v2.1.0.gif` for README embeds.

Optional: `export ANTHROPIC_API_KEY=...` and the shot list is written by Claude instead of templates — better visual metaphors per highlight. Without the key (or with `--no-llm`) the deterministic templates keep everything working with only the Runway key set.

### Useful flags

| Flag | What it does |
|---|---|
| `--dry-run` | Print shot list + credit cost, spend nothing |
| `--mock` | Full pipeline, placeholder clips, zero API calls |
| `--no-llm` | Deterministic prompt templates (only `RUNWAYML_API_SECRET` needed) |
| `--scenes N` | Max highlights → scenes (default 3) |
| `--seconds N` | Seconds per scene, 2–10 (default 5) |
| `--style-ref URL` | Brand image passed to `gen4_image` so every keyframe shares your palette |
| `--project NAME` | Title-card name (default: cwd name) |

Failure is graceful by design: a scene whose generation fails is retried once, then skipped with a warning — a partial video still assembles. One bad generation never costs you the run.

## What it costs

Runway credits are [$0.01 each](https://docs.dev.runwayml.com/guides/pricing/). Per video, at the defaults:

| Step | Model | Math | Credits |
|---|---|---|---|
| Keyframes | `gen4_image` @ 720p | 3 × 5 | 15 |
| Motion | `gen4.5` | 3 scenes × 5s × 12/s | 180 |
| **Total** | | | **195 ≈ $1.95** |

The $10 minimum credit purchase funds five videos. While iterating on prompts, test with single 2-second clips (`--scenes 1 --seconds 2` → 29 credits ≈ $0.29) before full runs — and `--dry-run` everything first.

## GitHub Action: video on every release

`release2reel` ships as a composite Action that fires on `release: published` and attaches the video to the release — no manual step.

```yaml
# .github/workflows/release2reel.yml
name: Release video
on:
  release:
    types: [published]

permissions:
  contents: write   # needed to upload the release asset

jobs:
  video:
    runs-on: ubuntu-latest
    steps:
      - uses: soos3d/release2reel@main
        with:
          runway_api_secret: ${{ secrets.RUNWAYML_API_SECRET }}
          # optional — LLM-written shot lists:
          anthropic_api_key: ${{ secrets.ANTHROPIC_API_KEY }}
```

Generation takes a few minutes per scene; the Action simply waits on Runway's async task API (`wait_for_task_output()` polls until the render is done). GitHub-hosted runners allow this comfortably — the job is idle-waiting, not compute-bound.

## Use it from a coding agent

[`SKILL.md`](SKILL.md) wraps the CLI in the [`runwayml/skills`](https://github.com/runwayml/skills) conventions (`rw-release-video`), so Claude Code / Cursor-style agents can invoke it: *"make a release video for v2.1"* → the agent runs the pipeline.

## Roadmap

- **Template gallery** — launch / bugfix / breaking-change scene moods
- **Localized variants** — multi-language overlay + audio versions of the same release video
- **Background audio** — `seed_audio` at 0.25 credits/sec adds ~$0.04/video
- **Characters presenter intro** — "your changelog, read by an avatar"
- **Node SDK port**
- **Promptless text-only mode** — gen4.5 supports text-to-video directly; keyframes kept for visual control
